# AI-Native User Flow · Juno

_Module 4. Generated by `M4 - AI User Flow Architect.html`. Paste over `04-ai-ux/user-flow.md`._

## Entry point

**Signal type:** Threshold crossed

A Slack thread in #escalations or #support-triage is tagged P0/P1 and crosses 5 messages within a 10-minute window.

**What they see instantly**

A "Juno is triaging this thread…" status badge appears inline in the thread within ~1 second, before ranking completes

## The flow

1. Retrieve — hybrid semantic+keyword pull, Top-K=15 over the four approved sources
Reason — score each candidate by severity × frequency, citing a Source ID per claim
Guardrail check — anything below 70% confidence or with contradicting sources is routed to NEEDS CLARIFICATION instead of ranked
Act — assemble the ranked table (max 5 rows), draft only, no autonomous Jira/Slack write
2. "Triaging this thread…" → "Cross-referencing 3 related tickets in ROCKET…" → "Ranking by severity × frequency…"
3. Confidence ≥70% → ranked output path. Confidence <70% → NEEDS CLARIFICATION path (no ranking presented at all).

## AI moments

**Placement:** Inline & Embedded

A ranked risk table (Rank | Risk/Theme | Customer signal | Source ID | Suggested action, max 5 rows) posted as a threaded reply directly in the #escalations thread, each row citing a Slack link, Jira key, or transcript timestamp.

The value-to-UX map assigns Risk mitigation to "Proactive flag + reason + one-click action" — not a full-page canvas, not a floating widget the PM has to notice. Posting inline, in the thread where the risk is already being discussed, is what keeps this "invisible by design": Juno shows up where the PM already is instead of requiring them to go find it.

## Fallbacks

**Kill switch**

Each ranked row carries an inline "Not P0 / demote" button and a "Needs human review" button. Clicking either does not call the Jira/Slack API directly — it only logs a correction and re-sorts the panel; the PM still manually applies any resulting change themselves.

**Training signal**

Demotes/overrides are logged as "prioritization correction" with the corrected rank + reason, tightening future severity×frequency scoring. Auto-triggered rankings are tagged separately from PM-invoked (pre-automation) ones, so accuracy/trust can be compared across the two cadences.

**Fail-safe**

No clearly relevant evidence, confidence <70%, or contradicting sources → the row posts as "NEEDS CLARIFICATION" with what's missing, never a confident-looking wrong ranking.
