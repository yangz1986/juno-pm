# Agent Workflow Spec (AWSpec) · Juno

_Module 5. Generated by `M5 - Agent Workflow Spec Builder.html`. Paste over `05-agentic-workflows/awspec.md`._

## Goal

Compress a P0/P1 escalation thread into a cited, ranked risk draft for PM review within minutes of the thread crossing a severity threshold (Risk mitigation).

**Primary actor:** Agent + Human-in-the-loop

## Trigger

New message posted in a Slack thread tagged P0 or P1 in #escalations or #support-triage, AND the thread has crossed 5 messages within a 10-minute window.

## Steps & tools

**Pattern:** ReAct (single-agent reason-act-observe loop)

| Step | Action | Tool / model | Guardrail |
|---|---|---|---|
| 1 | Read the triggering thread; retrieve related chunks (hybrid semantic+keyword, Top-K=15) across the four approved sources. | slack.read_thread(id) — read-only | Agent CAN read Slack #escalations/#support-triage (P0/P1-tagged only), Notion "RocketShip Product," Jira ROCKET (read-only), and transcripts explicitly shared in-thread. Agent CAN write only to a PM-facing draft/review surface. Agent CANNOT call Salesforce or any ARR/billing system — it must ask the PM. Agent CANNOT modify existing Jira tickets or Notion pages. Agent CANNOT post to #pm-daily, #escalations, or any external-facing channel without a human clicking approve. Agent CANNOT draft or send anything for external audiences (customers, prospects, press) under any circumstance. |
| 2 | Score severity × frequency per candidate; flag any source contradictions. | corpus.retrieve(query, k=15) — read-only, hybrid semantic+keyword across the four approved sources |  |
| 3 | If churn/expansion framing needs ARR/usage data and none is attached, ask the PM for it — do not estimate. | request_context(field) — not an external call; a prompt back to the PM asking for missing ARR/usage data (implements the system prompt's ask-don't-estimate rule) |  |
| 4 | If confidence <70% or sources conflict, mark NEEDS CLARIFICATION; otherwise draft the ranked table (max 5 rows, each row cited). | slack.post_draft(payload) — write, but restricted to the PM's private review surface only, never to #pm-daily or #escalations directly |  |
| 5 | Post the draft to a PM-only review surface for approve/edit/demote — never directly to #escalations or #pm-daily. | jira.draft_stub(payload) — prepares a ticket payload for the PM to review; the actual Jira create call fires only on an explicit human click, never on the agent's own decision |  |

**Schemas**

corpus.retrieve → {chunks:[{text, source_id, pillar, score}]} — source_id is mandatory on every returned chunk, so a citation-less claim is structurally impossible, not just a house rule.
request_context → {field_requested, reason} — surfaces to the PM as a plain question, not a silent skip.
jira.draft_stub → {draft_payload, status:"pending_human_action"} — the status field makes it structurally impossible for downstream code to treat this as a live ticket.

**Memory (in or out of scope)**

- **Episodic:** In-scope — logged "prioritization correction" events from the M4 kill switch (demote / needs-human-review clicks), tagged by thread + reason. Kept indefinitely to calibrate future scoring. Never used to auto-resolve a future thread without a human step.
- **Semantic:** In-scope — RocketShip's Notion product taxonomy, Juno's own system-prompt rules, PM scoring preferences. Refreshed on the same event/hourly cadence as the M3 PRD's sync rule. Out of scope: customer contract terms, ARR figures, or PII are never cached as "learned facts" — they're re-verified from source every run, per the system prompt's "never invent, leave blank if missing" rule.
- **Working:** In-scope — current thread content, retrieved top-15 chunks, current confidence score, any PM-supplied ARR/usage data for this run only. Discarded at end of run.
- **External:** Read: Slack (#escalations, #support-triage, P0/P1-tagged only), Notion ("RocketShip Product"), Jira (ROCKET, read-only), transcripts shared in-thread. Write: none directly to a live system — everything lands on the PM review surface first. Explicitly not connected: Salesforce/ARR/billing systems, any other Slack channel, any Jira project outside ROCKET, any external-facing channel (customer Slack, email, Intercom, status pages).

## Human-in-the-loop

PM clicks "Approve & post" before any draft reaches #pm-daily or #escalations — for every run, not only low-confidence ones. PM supplies ARR/usage data on request when churn/expansion framing needs it and it isn't already attached. PM's demote/"needs human review" clicks (the M4 Feedback Loop kill switch) are the only actions that ever adjust Juno's future scoring — the agent never updates its own memory unsupervised

## Success & failure

- **Done when:** Success: a cited draft (or a NEEDS CLARIFICATION note) reaches the PM review surface within the p95≤4s latency budget.
Failure: more than 2 tool/retrieval errors in one run → abort, log, notify the PM the run failed. No silent retry loop.
Escalation: confidence <70% on any row, contradicting sources, or missing required ARR/usage data → hand to the PM before any ranking is shown.
Timeout: hard wall-clock cap at 8s (2× the p95 target) → abort, return partial output explicitly flagged incomplete, never presented as a finished ranking.
- **Fails safe when:** Agent CAN read Slack #escalations/#support-triage (P0/P1-tagged only), Notion "RocketShip Product," Jira ROCKET (read-only), and transcripts explicitly shared in-thread. Agent CAN write only to a PM-facing draft/review surface. Agent CANNOT call Salesforce or any ARR/billing system — it must ask the PM. Agent CANNOT modify existing Jira tickets or Notion pages. Agent CANNOT post to #pm-daily, #escalations, or any external-facing channel without a human clicking approve. Agent CANNOT draft or send anything for external audiences (customers, prospects, press) under any circumstance.
